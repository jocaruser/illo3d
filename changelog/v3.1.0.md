# v3.1.0

No user-facing behaviour changes; shops open unchanged.

## Google backend testing — a live emulator instead of stubs

Google Drive/Sheets e2e tests now run against a real HTTP server:
[google-drive-api-mock](https://github.com/jocaruser/google-drive-api-mock),
a disk-backed emulator extracted from this repository
into its own spec-driven project (0BSD licensed).
`docker-compose.yml` pulls it by pinned tag as a `google-mock`
service; `make e2e-test` starts it alongside the app and points
the e2e Vite build at it via the three `VITE_GOOGLE_*_API_BASE`
overrides — the app reaches the mock exactly as it reaches real
Google. Tests seed state by writing plain CSV/JSON files into the
shared data directory and assert on the files the app leaves behind
— the same model the local-csv backend always had. See ADR-0014.

## Dev-mode Google emulation

- The three Google API base URLs accept build-time overrides
  (`VITE_GOOGLE_*_API_BASE`); production bundles keep
  the real Google endpoints inline.
- `pnpm run google-mock` starts the same emulator locally
  (state in `.google-mock-data/`).
  A `make` target wiring the full dev loop end to end
  (start the mock, point a dev-mode Vite server at it) is planned.

## Guardrails

- ESLint forbids `src/` from importing the emulator;
  CI and the Pages deploy verify the built bundle
  contains no trace of it.
