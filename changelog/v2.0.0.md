## What's Changed

### Audit Log System

Comprehensive audit log feature for tracking all entity mutations across the application.

* **Data Model**
  * `AuditEntry` type with full mutation tracking: `id`, `timestamp`, `actor`, `entity_name`, `entity_id`, `action`, `before_json`, `after_json`, `fieldsChanged`, `parent_entity_name`, `parent_entity_id`
  * `AuditEntityName` union covering all auditable entity types
  * `AuditAction` union: `create | update | archive | delete | restore`
  * `audit_log` registered as a first-class sheet in `SHEET_NAMES` and `SHEET_HEADERS`

* **UI & Navigation**
  * Dedicated Audit Log page at `/audit-log`
  * Accessible from main navigation with bilingual labels ("Audit Log" / "Registro de auditoría")
  * Full table display with all audit entry columns
  * Empty state handling with translated messages
  * Breadcrumb support: "Home > Audit Log"

* **Fixture Data**
  * `fixtures/audit-rich/` — comprehensive fixture set with 160+ audit entries demonstrating:
    * All 10 auditable entity types (client, job, piece, piece_item, inventory, lot, transaction, tag, tag_link, crm_note)
    * All 5 actions (create, update, archive, delete, restore)
    * Full cascade lifecycle: create → update → archive → delete → restore
    * Parent-child cascade tracking with `parent_entity_name`/`parent_entity_id`
    * Field-level change tracking with `fieldsChanged`
    * Multi-month timeline spanning January through April 2025
  * Consistent `audit_log.csv` in all fixture directories (`empty`, `happy-path`, `imports`, `kanban-stale-jobs`, `missingcolumn`, `audit-rich`)
